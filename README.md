## 保留规则
原文件只有一个 style 块和一个 script 块，均无标签属性。拆分入口将它们替换为同位置的 link 和外部 script。之后为通知、消费者个性化推荐、优惠券卡包、消费者活动筛选、评价流程、摊主付款核验、摊主专属搜索和电子名片管理调整了 HTML；CSS 仍与原提取内容逐字节一致。JavaScript 还增加了按钮选择、当前页导航、实时状态栏时钟、身份区分通知、消费者偏好推荐、优惠券状态联动、活动列表筛选排序、评价保存修改与摊主评分汇总、摊主付款凭证核验同步，以及摊主经营搜索、可保存编辑的名片资料和真实 QR 名片码。原始附件仍保存在 original 目录中。

原始 HTML 快照内含 521 个 SVG 元素；JavaScript 中动态生成的 SVG 仍保留在原 JavaScript 中。原 HTML 的资源引用均为文档内 # 片段，无独立外部静态资源文件引用；源码中的 SVG 命名空间 URL 不是下载资源。没有编造图片、字体、后端或业务逻辑。

## 运行
解压后打开 index.html。状态栏显示设备本地时间，并每 15 秒校准。消费者活动筛选会按已选城市、类型、日期和状态过滤演示活动，并按选择的方式排序；活动数据为本地样例，未接入活动发布后端。摊主首页及“活动与报名”仅展示活动目录中明确标注报名中且开始日期未到的活动，不会列出已结束或仅筹备中的活动；活动详情、报名意向均留在摊主端。摊主活动列表基于本地活动样例，未连接主办方实时发布服务，真实活动、名额与报名资格仍应以主办方发布信息为准。智能选位根据主营品类给出参考推荐，同时展示整个场地图的选择项；摊主可选择任何地图摊位提交意向，是否有空位及最终分配由管理者核实。选位和报名意向仅保存在当前浏览器，不会自动进入管理者真实业务系统。消费者可在“我的评价”查看并修改已提交的摊位评价；摊主经营数据会显示本地消费者对 C-03 摊位的评价，并根据评分汇总更新摊位综合分。摊主经营数据根据名片中的摊位名称、主营和介绍生成不同的演示指标及平台建议；品类不同会对应不同的高峰时段、经营重点和建议内容。“本场活动”“近 3 场”“全部历史”会切换不同区间的浏览、名片访问、收藏、领券统计与活动评分。经营数据为本地演示估算，不是接入平台采集的真实业务分析。摊主端提供独立的经营工具搜索；电子名片支持编辑并保存在当前浏览器，可展示及下载包含摊位标识、商户名和联系电话的 QR 名片码；编辑保存后，消费者摊位详情也会同步显示商户名称、主营介绍、优惠和联系电话。名片编辑支持选择最多 3 张 JPG、PNG、WebP 或 GIF 商品图（单张不超过 8 MB），会自动压缩并可预览、移除；保存后图片显示在名片上并在刷新后保留，首页待办会更新完善状态。商品图保存在当前浏览器本地存储。摊主可提交异常工单，管理者在“异常处理”接单、填写进展并标记完成；摊主上报记录和工单通知会随处理状态更新。工单保存在当前浏览器本地存储，并通过同源页面的存储事件同步；跨设备或真实多人使用仍需后端服务。摊主提交 C-03 水电费凭证后，管理者可在“收费管理”核验通过或退回；核验结果会同步更新摊主缴费状态。支付凭证及核验结果保存在当前浏览器本地存储，仅用于同一浏览器中的演示联动，不代表真实支付或财务入账。名片、评价、偏好与卡券也保存在当前浏览器本地存储，不同浏览器配置互相隔离；未接入账号服务或跨设备同步，因此真实消费者、摊主和管理者之间的数据共享仍需后端服务。消费者推荐依据当前浏览器保存的收藏、浏览、评价偏好排序；“有券”只显示当前消费者已领取且未核销的券。通知发送与收件箱在演示会话中联动；未连接真实短信、公众号或后端服务。原有摄像头、定位功能受浏览器权限与安全上下文限制；需要测试这些功能时，在项目目录运行 `python -m http.server 8000`，再访问 http://localhost:8000。

## 复核
在项目目录运行 `python verify.py`。工具校验原始附件、入口文件替换位置、提取资源与当前文件哈希，并使用 Node.js 检查 JavaScript 语法。校验说明、清单和工具属于交付辅助材料，不是原业务源码。

管理者活动管理、管理者首页、消费者活动目录和摊主报名列表现读取同一份活动目录。管理员可从活动表单发布活动或切换报名开关，变更保存在当前浏览器本地存储，并刷新同源页面；摊主列表只展示仍开放报名且尚未结束的活动。摊主签到记录与消费者按活动进行的打卡记录分开保存，并同步更新管理者现场签到页和消费者活动详情/打卡记录；消费者重复打卡会被拦截。管理者可在未签到时发送摊主签到提醒，提醒会进入同源页面的摊主通知中心并链接到签到页。活动、签到和提醒的共享仅限同一浏览器配置/同源页面的本地演示，不是跨设备实时服务；多人线上运营仍需接入后端与实时推送。
